**版本**：V3.0  
**日期**：2026-08-02  
**状态**：需求冻结，可直接编码  
**对应技术方案**：V3.0

---

## 1. 项目定位

- **平台**：Android（API 26+，即 Android 8.0 至 Android 14）
- **形态**：本地个人工具，不上架应用商店
- **核心能力**：通过 AccessibilityService 读取运满满司机APP订单列表 → 按用户预设规则匹配 → 强提醒通知用户 → 用户人工决定是否接单
- **红线**：工具不执行任何自动操作（不自动抢单、不自动拨号、不自动点击任何按钮）

## 3. 功能模块详述

### 3.1 模块A：权限引导与初始化

#### A.1 首次启动引导页
- **触发条件**：APP首次安装后打开，或某必要权限未开启时从后台唤起
- **页面内容**：
  - 标题："欢迎使用浏览助手"
  - 步骤1：开启无障碍服务（说明用途：读取运满满订单列表）
    - 按钮："去开启" → 跳转系统设置无障碍服务页面
    - 返回APP后自动检测是否已开启，未开启则按钮保持可点击，已开启则打勾并进入下一步
  - 步骤2：开启悬浮窗权限
    - 按钮："去开启" → 跳转系统悬浮窗权限设置
    - 返回后自动检测
  - 步骤3：加入电池白名单（可选但强烈建议）
    - 按钮："去设置" → 跳转电池优化设置
  - 步骤4：完成，进入主界面

#### A.2 权限状态常驻检测
- 每次回到APP前台时，检测无障碍服务和悬浮窗权限是否被系统回收
- 若被回收，弹出全屏遮罩提示："检测到无障碍服务已关闭，监控功能无法使用"，提供"去开启"按钮

#### B.2 交互细节

**备战区规则卡片：**
- 点击规则卡片 → 进入编辑页（预填充数据）
- 点击"激活" → 该规则进入匹配区，状态变为激活
- 点击"编辑" → 进入编辑页
- 点击"复制" → 复制该规则并命名为"XX规则-副本"，放入备战区
- 点击"删除" → 弹出确认对话框"确定删除此规则？删除后不可恢复"
- 至少保留一条规则，最后一条规则不允许删除（按钮置灰）

**匹配区规则卡片：**
- 点击"移除" → 该规则回到备战区，状态变为待命
- 点击"编辑" → 进入编辑页，编辑后仍保持在匹配区
- 匹配区内规则之间是 **OR 关系**（满足任意一套即提醒）

**一键操作：**
- "一键全部放入匹配区"：备战区所有规则全部激活，进入匹配区
- "一键全部移除回备战区"：匹配区所有规则全部移除，回到备战区

**出发地/目的地添加流程：**
1. 用户点击"+ 添加"按钮
2. 底部弹出全屏 BottomSheet 地区选择器
3. 选择器结构：
   ```
   ┌─────────────────────────────────────┐
   │  选择出发地              [关闭 X]  │
   ├─────────────────────────────────────┤
   │  [🔍 输入省份/城市/市区搜索]        │
   ├─────────────────────────────────────┤
   │  已选地区（可多选，无上限）          │
   │  [北京 ✕] [上海 ✕]                  │
   ├─────────────────────────────────────┤
   │  历史地区        [展开 ▼ / 收起 ▲]  │
   │  [泰州] [盐城] [南通] [宁波] ...    │
   ├─────────────────────────────────────┤
   │  请选择省/市/区                      │
   │  ┌────┬────┬────┬────┐             │
   │  │北京│天津│河北│山西│             │  ← 第一级：省级
   │  │内蒙│辽宁│吉林│黑龙江│           │
   │  │上海│江苏│浙江│安徽│             │
   │  │... │... │... │... │             │
   │  └────┴────┴────┴────┘             │
   │  （点击省份后，下方展开该市下辖区县）  │
   ├─────────────────────────────────────┤
   │  [清空筛选]        [确认]           │
   └─────────────────────────────────────┘
   ```
4. 选择逻辑：
   - 点击省级 → 该省级高亮，下方展开该省所有地级市
   - 点击市级 → 该市级高亮，下方展开该市下辖区县
   - 点击"全市" → 选中该市级（不含区县），已选列表添加"XX市"
   - 点击具体区县 → 选中该区县级，已选列表添加"XX市 XX区"
   - 点击已选标签的"✕" → 从已选列表移除
   - 点击"确认" → 关闭选择器，主界面已选标签更新
   - 点击"清空筛选" → 已选列表清空
   - **支持选"全国"** → 选后替换所有下级地区，匹配所有地区

**地区匹配逻辑：**
- 选"省" → 匹配该省所有市、区县
- 选"市" → 匹配该市所有区县
- 选"全国" → 匹配所有地区

**货源类型/车长/车型/重量/更多筛选交互：**
- 标签式多选，点击切换选中/未选中状态
- 选中：红色边框 + 红色文字 + 浅色红底
- 未选中：灰色边框 + 黑色文字 + 白色底

**装货时间交互：**
- "今天/明天/明天以后"三选一，选中高亮
- 精确时间：两个时间输入框，24小时制，点击弹出 TimePicker
- **兼容"昨天"装货**

**重量自定义交互：**
- 两个数字输入框，输入纯数字
- 若自定义输入与预设选项有重叠，预设选项自动高亮对应区间

**价格筛选交互：**
- 最低运费：数字输入框，只能输入正整数，单位"元"
- 电议两个选项：独立勾选框，可同时勾选、只勾一个、都不勾

#### B.3 数据校验
- 出发地和目的地至少选一个才能保存规则（否则提示"请至少选择一个出发地"）
- 最低运费输入非数字时，输入框边框变红，提示"请输入有效金额"
- 自定义重量最小值 > 最大值时，提示"最小重量不能大于最大重量"

### 3.4 模块D：悬浮窗控制面板

#### D.1 悬浮窗生命周期
- **显示时机**：用户从助手APP切换到运满满APP（或任何其他APP）时，悬浮窗自动显示
- **隐藏时机**：用户回到助手APP时，悬浮窗自动隐藏（避免遮挡助手APP自身界面）
- **权限**：依赖 SYSTEM_ALERT_WINDOW / TYPE_APPLICATION_OVERLAY

#### D.2 收起状态（迷你球）
```

- 🟢 绿色（#4CAF50）= 监控中
```

### 3.5 模块E：订单监控与匹配引擎

#### E.1 监控状态机
```
状态定义：
- IDLE：等待启动（悬浮窗显示，未点击开始）
- CHECKING：检测运满满页面状态中
- RUNNING：监控中（定时刷新+解析+匹配）
- PAUSED：已暂停（用户手动暂停或页面异常）
- ERROR：错误状态（无障碍服务被关闭等）

状态流转：
IDLE --(用户点击"开始")--> CHECKING
CHECKING --(页面正常)--> RUNNING
CHECKING --(页面异常)--> PAUSED
RUNNING --(用户点击"暂停")--> PAUSED
RUNNING --(运满满退出/切页)--> PAUSED
PAUSED --(用户点击"恢复")--> CHECKING
PAUSED --(用户点击"停止")--> IDLE
```

#### E.2 刷新与解析流程
1. 每隔 N 秒（用户设定，默认 5 秒，最低3秒，可调3-30秒）执行一次
2. 获取当前窗口根节点 `rootInActiveWindow`
3. 检测当前包名和 Activity 类名，确认是运满满订单列表页
4. 若页面不对 → 状态变为 PAUSED，悬浮窗显示异常提示
5. 若页面正确 → 执行下拉刷新手势（模拟从屏幕顶部向下滑动）
6. 等待 1 秒让列表加载完成
7. 遍历节点树，提取所有订单 item
8. 对每个订单 item 调用解析器，生成 Order 对象
9. 对每个 Order 调用规则引擎匹配（**匹配区内多套规则 OR 关系**）
10. 匹配成功且当日未提醒过 → 调用 AlertManager 触发强提醒

#### E.3 页面检测逻辑
- 包名检测：`packageName.contains("com.yymm") || packageName.contains("yunmanman")`
- Activity 类名：需运行时采集，维护一个白名单列表
- 页面特征文本：节点树中包含"筛选"、"智能排序"、"货源"、"去抢单"等关键词
- 三者满足其二即认为在订单列表页

#### E.4 订单解析字段（从节点树提取）

每单必须提取以下字段：

| 字段 | 类型 | 示例 | 提取方式 |
|---|---|---|---|
| orderId | String | 哈希生成 | 由出发地+目的地+货物+重量+时间戳生成MD5 |
| fromProvince | String | "苏州" | 文本正则匹配 |
| fromCity | String | "相城" | 文本正则匹配 |
| toProvince | String | "鸡西" | 文本正则匹配 |
| toCity | String | "鸡东" | 文本正则匹配 |
| cargoName | String | "电动叉车" | 关键词匹配 |
| weightMin | Float? | 0.5 | 正则提取数字 |
| weightMax | Float? | 0.7 | 正则提取数字 |
| vehicleLengths | List<String> | ["3.8", "4.2"] | 正则提取"X.X米" |
| vehicleTypes | List<String> | ["平板", "高栏"] | 关键词匹配 |
| priceAmount | Int? | 1200 | 正则提取数字，无则为null |
| priceText | String | "1200元/趟" 或 "电议" | 原始价格文本 |
| isDianyi | Boolean | true/false | 文本是否包含"电议" |
| loadTimeText | String | "明天 8-18点装货" | 文本提取 |
| distance | String? | "约589km" | 正则提取 |
| tags | List<String> | ["拼车", "送抢单特权"] | 关键词匹配 |
| rawTexts | List<String> | 所有文本 | 兜底匹配用 |

**价格解析特殊逻辑：**
- 文本含"电议" → `isDianyi = true`
- 文本含纯数字+"元" → `priceAmount = 数字值`
- 文本同时含"电议"和数字 → `isDianyi = true` 且 `priceAmount = 数字值`（归类为"电议有价格"）
- 文本只含"电议"无数字 → `isDianyi = true` 且 `priceAmount = null`（归类为"电议无价格"）

**"不限车长"/"不限车型"处理：**
- 解析时 `vehicleLengths`/`vehicleTypes` 为空列表
- 匹配时该字段规则自动通过（任何车都匹配）

#### F.1 规则数据结构
```kotlin

    val id: String,
    val name: String,
    val ruleStatus: RuleStatus,  // STANDBY(备战区) / ACTIVE(匹配区)

    val loadTimeEnd: Long?,    // 时间戳，CUSTOM时用

    // 重量
    val weightRanges: Set<WeightRange>,  // 预设区间
    val weightMin: Float?,     // 自定义最小
    val weightMax: Float?,     // 自定义最大

    // 价格筛选

    val includeDianyiWithPrice: Boolean,   // 电议有价格

    val requireManyunbao: Boolean,
    val requireDepositRefundable: Boolean,
    val requirePrivilege: Boolean
)

data class LocationRule(
    val province: String,
    val city: String? = null,
    val district: String? = null
) {
    fun matches(orderProvince: String, orderCity: String?): Boolean {
        if (province != orderProvince) return false
        if (city != null && city != orderCity) return false
        return true
    }
}
```

#### F.2 匹配算法伪代码（宽松模式 + OR关系 + 优先级）
```
function match(order, activeRules):
    // activeRules = 匹配区内所有规则（无上限）

    for each rule in activeRules:
        if matchSingleRule(order, rule):
            return true  // OR关系：满足任意一套即提醒

    return false

function matchSingleRule(order, rule):
    if rule.ruleStatus != ACTIVE: return false

    // ========== 第一优先级：出发地与目的地 ==========
    // 1. 出发地匹配（OR）
    fromMatch = rule.fromLocations.isEmpty() || 
        rule.fromLocations.any { it.matches(order.fromProvince, order.fromCity) } ||
        rule.fromCustomPoints.any { point -> order.rawTexts.any { it.contains(point) } }
    if !fromMatch: return false

    // 2. 目的地匹配（OR）
    toMatch = rule.toLocations.isEmpty() || 
        rule.toLocations.any { it.matches(order.toProvince, order.toCity) } ||
        rule.toCustomPoints.any { point -> order.rawTexts.any { it.contains(point) } }
    if !toMatch: return false

    // ========== 次要优先级：其他筛选条件 ==========
    // 3. 货源类型匹配（OR）
    cargoMatch = rule.cargoTypes.isEmpty() ||
                 rule.cargoTypes.any { type ->
                     when type:
                         FULL_VEHICLE -> order.tags.contains("整车货")
                         PREMIUM -> order.tags.contains("优车货")
                         INSTANT -> order.tags.contains("即时单")
                         CARPOOL -> order.tags.contains("拼车货")
                         else -> false
                 }
    if !cargoMatch: return false

    // 4. 车长匹配（OR）— 宽松模式：订单"不限车长"时自动通过
    lengthMatch = rule.vehicleLengths.isEmpty() || 
                  order.vehicleLengths.isEmpty() ||  // "不限车长"
                  rule.vehicleLengths.any { len -> order.vehicleLengths.contains(len) }
    if !lengthMatch: return false

    // 5. 车型匹配（OR）— 宽松模式：订单"不限车型"时自动通过
    typeMatch = rule.vehicleTypes.isEmpty() || 
                order.vehicleTypes.isEmpty() ||  // "不限车型"
                rule.vehicleTypes.any { type -> order.vehicleTypes.contains(type) }
    if !typeMatch: return false

    // 6. 装货时间匹配（兼容"昨天"）
    timeMatch = when rule.loadTimeOption:
        ANY -> true
        TODAY -> order.loadTimeText.contains("今天")
        TOMORROW -> order.loadTimeText.contains("明天")
        AFTER_TOMORROW -> order.loadTimeText.contains("后天") || order.loadTimeText.contains("明天以后")
        CUSTOM -> parseTime(order.loadTimeText) in range(rule.loadTimeStart, rule.loadTimeEnd)
    if !timeMatch: return false

    // 7. 重量匹配（OR）— 宽松模式：字段缺失/不完整时自动通过
    weightMatch = if (rule.weightRanges.isEmpty() && rule.weightMin == null && rule.weightMax == null):
        true
    else if (order.weightMin == null && order.weightMax == null):
        true  // 字段缺失，自动通过
    else:
        val orderMin = order.weightMin ?: 0f
        val orderMax = order.weightMax ?: Float.MAX_VALUE
        val inPreset = rule.weightRanges.any { range ->
            orderMin >= range.min && orderMax <= range.max
        }
        val inCustom = (rule.weightMin == null || orderMin >= rule.weightMin) &&
                       (rule.weightMax == null || orderMax <= rule.weightMax)
        inPreset || inCustom
    if !weightMatch: return false

    // 8. 价格匹配（宽松模式核心）
    priceMatch = matchPrice(order, rule)
    if !priceMatch: return false

    // 9. 更多筛选（AND）
    extraMatch = (!rule.requireHighCredit || order.tags.contains("高信用货主")) &&
                 (!rule.requireManyunbao || order.tags.contains("满运宝")) &&
                 (!rule.requireDepositRefundable || order.tags.contains("订金可退")) &&
                 (!rule.requirePrivilege || order.tags.contains("送抢单特权"))
    if !extraMatch: return false

    return true

// 价格匹配核心逻辑（宽松模式）
function matchPrice(order, rule):
    // 情况1：订单是电议
    if order.isDianyi:
        if order.priceAmount != null:
            // 电议有价格
            if !rule.includeDianyiWithPrice: return false
            if rule.minPrice != null && rule.minPrice > 0 && order.priceAmount < rule.minPrice:
                return false
            return true
        else:
            // 电议无价格
            return rule.includeDianyiWithoutPrice  // 不受最低运费限制

    // 情况2：订单不是电议，有明确价格
    if order.priceAmount != null:
        if rule.minPrice != null && rule.minPrice > 0 && order.priceAmount < rule.minPrice:
            return false
        return true

    // 情况3：订单无价格且不是电议（字段缺失，宽松模式自动通过）
    return true  // 信息不完整仍推送，由真人判断
```

#### G.3 提醒方式实现
- **弹窗**：启动 `AlertPopupActivity`（`FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TOP`）
- **震动**：`Vibrator.vibrate()`，时长用户可配置
- **响铃**：`MediaPlayer` 播放音频文件，音量用户可配置
- **语音播报**：`TextToSpeech` 引擎，中文播报，语速用户可配置
  - 播报文本模板："发现新订单，从{出发地}到{目的地}，运费{价格}，重量{重量}吨，请查看。"

  - **不做扩展**：不播报车型、车长、距离、货主评分、装卸次数等额外信息

#### G.4 去重机制
- 以 `orderId`（MD5哈希）为唯一标识
- 当日已提醒的 orderId 存入内存 `Set<String>` + Room 数据库 `HistoryRecord` 表
- 每天 00:00 自动清空内存缓存（数据库记录保留供历史查看）

#### G.5 多订单处理
- 匹配到多个订单时，处理方式由用户设置：
  - 排队依次弹窗
  - 或只弹最新的一个（覆盖）
